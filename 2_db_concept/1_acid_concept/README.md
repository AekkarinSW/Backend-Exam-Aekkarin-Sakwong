## Response Section

ACID คือหลักที่ช่วยให้การทำ transaction กับฐานข้อมูลมีความถูกต้องและเชื่อถือได้ โดยแต่ละตัวอักษรมีความหมายดังนี้

- **Atomicity** — งานใน transaction เดียวกันต้องสำเร็จทั้งหมดหรือยกเลิกทั้งหมด เช่น การโอนเงินต้องหักจากบัญชีต้นทางและเพิ่มให้บัญชีปลายทางพร้อมกัน ถ้าขั้นตอนใดล้มเหลวต้อง rollback ทั้งชุด
- **Consistency** — หลังจบ transaction ข้อมูลยังต้องเป็นไปตามกฎของระบบ เช่น primary key ต้องไม่ซ้ำ, foreign key ต้องอ้างถึงข้อมูลที่มีอยู่จริง และยอดเงินต้องไม่ผิดเงื่อนไขทางธุรกิจ
- **Isolation** — transaction ที่ทำงานพร้อมกันไม่ควรเห็นข้อมูลระหว่างทางของกันและกันจนทำให้ผลลัพธ์ผิด ฐานข้อมูลจะควบคุมเรื่องนี้ผ่าน locking, MVCC และ isolation level
- **Durability** — เมื่อ commit สำเร็จแล้ว ข้อมูลต้องยังอยู่ แม้โปรแกรมหรือเครื่องฐานข้อมูลจะหยุดทำงานภายหลัง

### ฐานข้อมูลและแอปพลิเคชันรับผิดชอบส่วนใด

**ฝั่งฐานข้อมูล**

- ดูแลกลไก `BEGIN`, `COMMIT` และ `ROLLBACK`
- บังคับใช้ constraint เช่น primary key, foreign key, unique และ check
- จัดการ concurrent transaction ตาม isolation level
- เก็บ transaction log และกู้คืนข้อมูลที่ commit แล้วเมื่อระบบมีปัญหา

**ฝั่งแอปพลิเคชัน**

- กำหนดว่าแต่ละ transaction ควรเริ่มและจบตรงไหน
- ตรวจสอบ business rule ที่เขียนเป็น database constraint ได้ไม่ครบ
- จัดการ exception รวมถึงเลือกว่าจะ retry หรือยกเลิกงาน
- ไม่เปิด transaction ทิ้งไว้นานเกินจำเป็น
- ป้องกันการทำงานซ้ำเมื่อมีการ retry เช่น ใช้ idempotency key ในงานที่เหมาะสม

สรุปแล้ว ฐานข้อมูลเป็นกลไกหลักที่ทำให้ transaction มีคุณสมบัติ ACID ส่วนแอปพลิเคชันต้องแบ่งขอบเขต transaction และใช้กลไกเหล่านั้นให้ตรงกับกฎของระบบ
