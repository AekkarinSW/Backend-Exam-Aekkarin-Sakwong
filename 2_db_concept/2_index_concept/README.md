## Response Section

Database index เป็นโครงสร้างข้อมูลที่ช่วยให้ฐานข้อมูลหาข้อมูลได้เร็วขึ้น แนวคิดคล้ายสารบัญของหนังสือ คือไม่ต้องเปิดอ่านทุกหน้าเพื่อหาหัวข้อที่ต้องการ

ตัวอย่างเช่น ถ้าระบบค้นหานักเรียนด้วย `classroom_id` บ่อย การมี index ที่คอลัมน์นี้จะช่วยลดการอ่านข้อมูลทั้งตาราง

### ข้อดี

- ทำให้ query ที่ใช้ `WHERE` เร็วขึ้น
- ช่วยการ `JOIN` เมื่อสร้าง index บนคอลัมน์ที่ใช้เชื่อมตาราง
- อาจช่วย `ORDER BY` หรือ `GROUP BY` ได้ เมื่อรูปแบบ query ตรงกับลำดับของ index
- ใช้ `UNIQUE INDEX` เพื่อป้องกันข้อมูลซ้ำได้
- ลดจำนวนแถวหรือหน้าข้อมูลที่ฐานข้อมูลต้องอ่าน

### ข้อจำกัด

- ใช้พื้นที่จัดเก็บเพิ่ม
- ทำให้ `INSERT`, `UPDATE` และ `DELETE` มีงานเพิ่ม เพราะต้องปรับ index ตามข้อมูล
- การสร้าง index มากเกินไปอาจทำให้การเขียนข้อมูลช้าลงโดยไม่ช่วย query จริง
- คอลัมน์ที่มีค่าซ้ำมาก หรือ query ที่ต้องอ่านเกือบทั้งตาราง อาจไม่ได้ประโยชน์จาก index
- composite index ต้องเรียงคอลัมน์ให้สอดคล้องกับ query ที่ใช้งาน
- query optimizer อาจเลือก full table scan ถ้าประเมินว่าเร็วกว่า

ดังนั้นผมจะเริ่มจากดู query ที่ใช้งานจริง โดยเฉพาะคอลัมน์ใน `WHERE`, `JOIN` และ `ORDER BY` แล้วตรวจ execution plan ก่อนและหลังเพิ่ม index แทนการสร้าง index ให้ทุกคอลัมน์
